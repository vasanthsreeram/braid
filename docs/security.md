# Storage and access model

A principal is a verified WorkOS `sub` plus selected `org_id`, or a user-owned personal tenant if no organization claim exists. The application uses a client-pinned JWKS, RS256, explicit issuer, expiry, issued-at, session-ID and optional audience verification. WorkOS org roles grant no implicit repository access. Owner or explicit same-tenant grant must authorize each private read/write, including Batch and object downloads. Unauthorized/missing resources share 404. Public browsing is gated by an explicit deployment setting and confirmed publication; evaluation leaves that setting false. LFS remains authenticated even for a public Git repository.

D1 policy uses primary reads (no replicas/sessions enabled here). Immediate direct-grant revocation is tested locally. WorkOS membership/session revocation event handling is deferred; JWT access lasts until token expiry. The browser cookie adds a 15-minute limit and has Secure, HttpOnly, SameSite=Lax, `__Host-` attributes. Unsafe cookie requests require exact Origin; API/LFS credential requests use explicit authorization. Logout clears the browser cookie only; refresh and provider session revocation are not yet implemented. OAuth state/verifier use an encrypted 10-minute flow cookie, PKCE S256, exact callback and fixed WorkOS origins. No fake login is supplied by the deployed Worker.

## Object representation

Whole-file Git LFS SHA256 OID → immutable **repo-scoped** manifest → immutable **tenant-scoped** chunk hashes. Object existence is never queried in a tenant-wide manifest namespace. Unauthorized callers cannot probe chunk/manifests, and no raw chunk or bucket route exists. Files/pointers, commits and trees use Artifacts; R2 is a separate large-object plane. Converting existing ordinary blobs to LFS rewrites history; no preserving-migration claim.

Algorithm `gear32-v1`: fixed xorshift32 gear table seed 0x51f15e; update `(rolling << 1) + gear[byte]` modulo 2³²; cut after min 512 KiB when low 20 bits are zero, or max 4 MiB; reset hash after cut. Target is nominal 1 MiB, not guaranteed mean. Final chunk may be shorter. This is a deterministic gear CDC equivalent, not normalized FastCDC. The version/table/parameters and golden fixture hashes are pinned. The CDC buffer is 4 MiB plus a bounded emitted chunk; file/chunk SHA256 is incremental. Downloads read and verify one ≤4 MiB chunk at a time. Total invocation memory also includes upstream stream buffers and concurrent requests; local process RSS is not a Workers memory proof.

Ingest checks safe size ≤256 MiB, every chunk hash/length, and full SHA/size. Conditional create prevents replacing a chunk/manifest. Existing chunks are verified before reuse. Manifest publication occurs last. A failed upload may leave verified but unreachable chunks; it cannot expose an object or publish a wrong hash. Duplicate concurrent uploads converge on the same deterministic immutable manifest. Tenant sharing saves storage, with repo-level manifests preventing cross-repo existence disclosure. Forking copies validated private manifest associations within the same tenant without duplicating chunks.

Manifest validation fixes algorithm/version/bounds, OID, chunk entry count, lengths and total. Storage paths derive from validated IDs/hashes rather than arbitrary manifest paths. Downloads check each chunk before emission and check whole-file order/hash before emitting the last chunk; corrupt/missing chunks abort the body. Once headers are sent, integrity failures cannot change HTTP status. Consumers must reject incomplete bodies/hash mismatches; actual git-lfs checkout integrity was checked. No resumable/range support: Range returns 416. No cache for private bodies.

## Standard LFS uploads and the request limit

Standard basic clients perform **one PUT per whole object**; they do not automatically multipart. Native Workers request limits remain 100 MB on Free/Pro zones (200 MB Business), regardless of streaming. Local 112 MiB success therefore proves only the loopback endpoint. Production Batch instead signs a 10-minute R2 S3 PUT to a random, tenant/repo-scoped staging key, with signed Content-Length and Content-Type. No GET/bucket authority is returned. The standard verify POST binds a D1 ticket to tenant/repo/OID/size/expiry, reads staging through the R2 binding, validates CDC/whole bytes, publishes the manifest, then deletes that staging object. Credentials and provider entitlement for this path are missing; actual R2 length enforcement, client behavior, CPU and limits **remain live blockers**. No above-limit Cloudflare compatibility claim is made.

An authorized URL holder can repeat a signed PUT until expiry. Verify is idempotent once a correct manifest exists; subsequent staging writes cannot alter it. Staging retention needs a dedicated-bucket lifecycle rule restricted to `v1/tenants/*/staging` or an explicit bounded maintenance job; no lifecycle rule was remotely installed. A verify interrupted after publication can retain staging. Unreachable chunks are retained safely. **No automatic chunk GC**: naïve mark/delete can race ingest and destroy live chunks. Future GC must fence ingest, enumerate committed references and retain a grace period. Currently losing storage through orphans is preferred over corrupting published files.

## Remaining controls

Production is not deployed and must not be launched as a general multi-tenant service yet. Durable per-tenant upload/repo budgets, abuse/rate admission, native token registry/revocation, session/webhook lifecycle, fork/import reconciliation, garbage collection, and an atomic canonical publisher remain required launch work. Benchmark defaults are finite: ≤3 LFS repetitions, 101–128 MiB fixtures, five versions, ≤5 code repetitions, two task clients, 60-second child deadlines. The Worker advertises no unauthenticated admin/health route and never calls child_process; all native Git subprocesses are confined to `scripts/`.

No Actions workflows exist. Imported GitHub URLs use strict HTTPS/github.com reconstruction; no embedded credentials, query, fragment, port, arbitrary scheme, submodule or LFS traversal. Native import fidelity/SSRF beyond the native importer boundary is untested. Source is returned as plain-text attachments with nosniff, never rendered as repository HTML. UI uses textContent. Review approval is an immutable decision, not evidence of a successful merge or CI run.
