# Storage and access model

A principal is a verified WorkOS `sub` plus selected `org_id`, or a user-owned personal tenant if no organization claim exists. The application uses a client-pinned JWKS, RS256, explicit issuer, expiry, issued-at, session-ID and optional audience verification. WorkOS org roles grant no implicit repository access. Owner or explicit repository grant must authorize each private read/write, including Batch and object downloads. Personal repositories permit explicit sharing across personal tenants; organization repositories require current membership in the selected owning organization. A task inherits its canonical tenant. Its author needs a parent contributor grant; independently shared task readers have no parent authority. Unauthorized/missing resources share 404. Public browsing is gated by an explicit deployment setting and confirmed publication; evaluation leaves that setting false. LFS remains authenticated even for a public Git repository.

D1 policy uses primary reads. Each authenticated request verifies the signed access token, the actual active WorkOS session, and, for an organization, current active membership through the provider. A provider outage fails closed. The bounded session/membership queries inspect at most 100 records; missing results deny access. The browser session is an encrypted seven-day envelope containing access/refresh credentials, with Secure, HttpOnly, SameSite=Lax, `__Host-` attributes. Access-token expiry triggers the explicit refresh endpoint; rotated tokens replace the envelope. POST refresh, organization switch and logout require exact Origin. Logout writes a local session denial, revokes tracked native credentials, revokes the WorkOS session, clears the cookie and redirects to provider logout. The dedicated WorkOS client/issuer and URLs are configured, but its server API key is missing, so these session contracts have only labeled test-provider verification. Browser reloads with an expired access token offer a same-origin POST session-resume form; API requests use serialized refresh.

OAuth uses an encrypted ten-minute state/verifier cookie, PKCE S256, exact callback and fixed WorkOS endpoints. WorkOS roles confer no implicit repository authority. Seven-day invitation links are bound to a verified provider email, require active selected organization membership where applicable, and recheck the issuer's current administration/membership. A single D1 update plus trigger accepts and grants atomically. Invitation role changes revoke existing native credentials. Access changes are blocked while canonical publication is fenced. Private missing/unauthorized objects both return 404.

Native Artifacts tokens cannot constrain arbitrary refs. Canonical write tokens are never issued to users; regular writers receive only controlled private task-repository credentials. Authenticated public readers may mint read credentials only while explicit public visibility is enabled; anonymous native token issuance is denied. Read/task-write tokens last 60 seconds, are registered without plaintext, and are reauthorized after issuance. Grant/visibility/logout mutations revoke tracked native tokens. External WorkOS revocation immediately blocks application access but already-issued native tokens can retain authority for at most 60 seconds; no instant native revocation via WorkOS webhook is claimed.

## Object representation

Whole-file Git LFS SHA256 OID → immutable **repo-scoped** manifest → immutable **tenant-scoped** chunk hashes. Object existence is never queried in a tenant-wide manifest namespace. Unauthorized callers cannot probe chunk/manifests, and no raw chunk or bucket route exists. Files/pointers, commits and trees use Artifacts; R2 is a separate large-object plane. Converting existing ordinary blobs to LFS rewrites history; no preserving-migration claim.

Algorithm `gear32-v1`: fixed xorshift32 gear table seed 0x51f15e; update `(rolling << 1) + gear[byte]` modulo 2³²; cut after min 512 KiB when low 20 bits are zero, or max 4 MiB; reset hash after cut. Target is nominal 1 MiB, not guaranteed mean. Final chunk may be shorter. This is a deterministic gear CDC equivalent, not normalized FastCDC. The version/table/parameters and golden fixture hashes are pinned. The CDC buffer is 4 MiB plus a bounded emitted chunk; file/chunk SHA256 is incremental. Downloads read and verify one ≤4 MiB chunk at a time. Total invocation memory also includes upstream stream buffers and concurrent requests; local process RSS is not a Workers memory proof.

Ingest checks safe size ≤256 MiB, every chunk hash/length, and full SHA/size. Conditional create prevents replacing a chunk/manifest. Existing chunks are verified before reuse. Manifest publication occurs last. A failed upload may leave verified but unreachable chunks; it cannot expose an object or publish a wrong hash. Duplicate concurrent uploads converge on the same deterministic immutable manifest. Tenant sharing saves storage, with repo-level manifests preventing cross-repo existence disclosure. Forking copies validated private manifest associations within the same tenant without duplicating chunks.

Manifest validation fixes algorithm/version/bounds, OID, chunk entry count, lengths and total. Storage paths derive from validated IDs/hashes rather than arbitrary manifest paths. Downloads check each chunk before emission and check whole-file order/hash before emitting the last chunk; corrupt/missing chunks abort the body. Once headers are sent, integrity failures cannot change HTTP status. Consumers must reject incomplete bodies/hash mismatches; actual git-lfs checkout integrity was checked. No resumable/range support: Range returns 416. No cache for private bodies.

## Standard LFS uploads and the request limit

Standard basic clients perform **one PUT per whole object**; they do not automatically multipart. Native Workers request limits remain 100 MB on Free/Pro zones (200 MB Business), regardless of streaming. Local 112 MiB success therefore proves only the loopback endpoint. Production Batch instead signs a 10-minute R2 S3 PUT to a random, tenant/repo-scoped staging key, with signed Content-Length and Content-Type. No GET/bucket authority is returned. The standard verify POST binds a D1 ticket to tenant/repo/OID/size/expiry, reads staging through the R2 binding, validates CDC/whole bytes, publishes the manifest, then deletes that staging object. Bucket-scoped S3 signing credentials for this path are missing; actual R2 length enforcement, client behavior, CPU and limits **remain live blockers**. No above-limit Cloudflare compatibility claim is made.

An authorized URL holder can repeat a signed PUT until expiry. Verify is idempotent once a correct manifest exists; subsequent staging writes cannot alter it. The dedicated remote bucket has a one-day lifecycle expiry restricted to the new `staging-v1/` prefix. Chunk/manifests remain outside it. Public r2.dev access is disabled. A verify interrupted after publication can retain staging. Unreachable chunks are retained safely. **No automatic chunk GC**: naïve mark/delete can race ingest and destroy live chunks. Future GC must fence ingest, enumerate committed references and retain a grace period. Currently losing storage through orphans is preferred over corrupting published files.

## Git publication, import and recovery

An immutable proposal pins base/candidate hashes and requires bounded descendant ancestry validation. Approval is an explicit decision; integration is a separate admin action. A D1 conditional update fences the publishing intent. The trusted publisher checks the current canonical ref, streams a checksum-verified pack and sends the exact expected old SHA to native receive-pack. Native compare-and-update rejects stale heads, including an actual simultaneous-publisher race verified remotely. Only an exact unpack/ref success receipt plus confirmed actual head becomes merged. There is no force overwrite, CI requirement, repository build or repository code execution.

Failures retain the fence because a disconnected request can still have published. Reconciliation confirms the candidate, or marks a divergent ref failed. A ref still at base retains the fence: it cannot prove an in-flight publisher has stopped. That case requires operator investigation; no unsafe blind retry or automatic fence timeout is implemented. Failed create/fork/import operations retain a recorded branch/tag source snapshot. Reconciliation checks destination refs, inherits validated LFS associations and revokes initial capabilities before marking ready; an incomplete or mismatched snapshot cannot produce fake success.

Imported GitHub URLs use strict HTTPS/github.com identity reconstruction and no embedded credentials, query, fragment, port, arbitrary scheme, submodule or LFS traversal. Native full-history import is tried first. Its measured 40 MB limit can trigger a Git smart HTTP streaming fallback into an empty new destination, limited to 128 MiB pack/512 branch/tag refs. Source refs before/after and destination tips must match; provider still enforces 32 MB blob/1 GB repo limits. There is no shallow or history-rewrite fallback. GitHub LFS objects, submodules and platform metadata are explicitly separate migrations. The selected remote migration had no historical LFS pointers or checkout submodules, and its full reachable objects/commits/file content were compared. Source was unchanged and imported code/dependencies were never run.

Source is returned as plain-text attachments with nosniff, never rendered as repository HTML. UI uses textContent. Remote Worker assets and APIs require real WorkOS; no loopback identity/admin/test bypass is bundled. Evaluation public visibility is disabled. All direct provider test destinations require native tokens, independently of app ownership; the retained migration is not attached to a fabricated WorkOS user.

## Deployment boundary and exclusions

The dedicated private evaluation Worker/D1/R2/Artifacts deployment exists and unauthenticated denials were tested. Dedicated WorkOS and R2 signing credentials are still missing. No fully authenticated production flow or above-limit remote LFS success is claimed. General service admission/rate and per-tenant storage budgets, orphan GC and range/resume are not implemented. Bounds exist for JSON bodies, import packs/refs, ancestry/diff, LFS objects/batches/manifests and developer tests; these are not a comprehensive abuse-control system.

Native CI/check runners, Agents SDK, Sandbox/Containers, model-driven edits/tests and executing imported repositories are excluded, not launch dependencies. Benchmark shell scripts and synthetic app tests are developer tooling. The Worker never calls child_process; local Git subprocesses are confined to development scripts. Benchmark defaults remain finite and all prior raw/report assets are preserved unchanged.

Provider contracts: [WorkOS sessions](https://workos.com/docs/authkit/sessions), [session list/revoke API](https://workos.com/docs/reference/authkit/session). Real provider account configuration is required before the implemented contract can be declared live.

Contribution profiles are private, self-only API reads. They use the same current tenant, canonical/task and repository grants as source browsing, rather than trusting a repository listing as an authorization check. They expose no other user's aggregate profile. Daily counts use UTC author dates and unique reachable Git object IDs; a verified email match is attribution, not proof of Git authorship. Accessible forks and repeated copies count once; inaccessible repositories do not contribute names, links or counts. Bounded partial scans, unreachable commits, former emails and unregistered provider-only migration repositories are disclosed in [the current result](auth/result.md).

Gitflare's responses use `no-store, no-transform` to prevent private caching and Cloudflare analytics injection without changing shared zone settings. `__Host-` cookies have no Domain attribute, and HTTP/legacy Worker-origin reads redirect to the canonical HTTPS hostname. Unsafe requests to those aliases receive 421 and cannot mutate sessions/data.
